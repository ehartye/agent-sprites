# File import and progressive project access

This is the concrete second milestone of the approved large-project authoring design. It does not replace the existing JSON import route or require an in-place file/database migration.

## Units

- `server/io/bounded-input.js`: bounded stream-to-owned-file input, byte/hash progress, abort and diagnostic collection. It never owns caller files or deletes a shared temporary root.
- `server/build/generator-input.js`: spawn a declared generator, spool stdout through the bounded input helper, collect bounded stderr, enforce timeout/abort, parse the owned result and retain the existing operation/report contract.
- `server/import/project-validation.js`: portable import budgets and metadata validation shared by worker and old/new import wiring where compatible.
- `server/import/project-import-worker.js`: parse and validate an owned JSON file off the server event loop, write a validated project snapshot and return only its identity/summary. Parsing still materializes a project inside the worker; record this cost honestly.
- `server/import/project-import-jobs.js`: job lifecycle, worker concurrency, per-job ownership, cancellation, expiry and cleanup.
- `server/web/api/project-import-routes.js`: small job control requests and raw streamed upload. Mounted before the generic JSON body parser; enforce existing loopback/origin rules.
- `server/session-activation.js`: transactionally persist a prospective session and portable metadata, then publish active state. No active state changes before all required steps succeed.
- `server/web/project-view.js`: progressive summary/revision and bounded cell payloads, plus a common project publication helper that avoids constructing expanded snapshots when only progressive clients are present.
- `server/web/public/js/project-frames.js`: bounded session/revision-pinned browser frame cache/request scheduler. Sparse data cannot be mistaken for empty authored cells.
- `server/web/public/js/project-import.js`: direct File upload, byte progress, polling, cancel and activation; no complete-file browser text parse.

Exact helper names can be adjusted for an existing equivalent abstraction; units must retain these ownership boundaries rather than growing one route file.

## Job API

All routes are under `/api/workbench/imports`. IDs are unguessable, generated by the server; filenames never select filesystem destinations.

| Request | Behavior |
| --- | --- |
| `POST /` with `{filename, encoding?: "json" | "gzip"}` | Allocate a uniquely owned job and pin the current session/project identity. Return `{ok:true,data:{id,state:"uploading",...limits}}`. |
| `PUT /:id/file` with raw File bytes | Stream input to the job, with independent source and expanded byte counters/limits. Return HTTP 202 after upload; validation continues off-thread. |
| `GET /:id` | Return state, received/expanded byte counts, source hash, bounded diagnostics and validation result; never return a whole project or temporary filesystem paths. |
| `POST /:id/activate` | Activate a ready job only if the originating session/project still matches. Return the new session identity. Duplicate activation is idempotent for that completed job. |
| `DELETE /:id` | Abort that job's streams/worker and remove its temporary files. Cancellation remains possible after another session becomes active. Completed sessions are never deleted by cancel. |

States are uploading, validating, ready, activating, complete, failed and canceled. Failed/canceled jobs never activate. A ready job does not activate itself. Pinning must detect open-other/open-original races, not only a matching friendly name. Control requests have a small JSON limit. Raw upload bypasses the generic JSON parser without increasing its 64 MiB policy for unrelated routes.

Use explicit trusted server-side policy defaults, reported in the job response: source/expanded byte budgets, declared cell and expanded shape budgets, validation timeout/worker resource limits and maximum active/validating jobs. Request bodies cannot increase them. Tests use smaller trusted policy settings to exercise limits cheaply. The real representative import must pass under documented defaults; raising a number without measuring the expanded model is not acceptance.

Activation reuses current metadata and session semantics. Worker validation checks shape-group structure before readiness, while transaction rollback still protects against a storage/metadata failure during activation. Imported input files and earlier sessions remain unchanged. Worker output is checked against its size/hash receipt before activation. Shutdown/expiry only cleans directories owned by this service and never sweeps unrelated user temporary files.

## Progressive browser protocol

The updated browser opts in via its WebSocket connection; legacy connections still receive ordinary expanded project messages. Project publication supplies a metadata summary to progressive connections and constructs a full snapshot only when a legacy consumer explicitly needs it. A summary includes dimensions/grid, palette/background, cell labels/counts, timing/tags/groups, session identity and revision; large geometry and construction snapshots are fetched deliberately.

Bounded cell retrieval returns complete requested cells with the session/revision they represent. Limit both requested cell count and serialized response bytes. Session changes reject a stale request; revision changes force refresh rather than silently caching mismatched data. The client prioritizes the selected frame and visible thumbnail needs, prefetches only a small nearby window and evicts bounded cached data. Obsolete requests are aborted or ignored, and cached references cannot point into a different session.

Keep API edit requests pinned to the active session. Local updates and redraw coalescing must preserve selected shapes and valid render caches; unknown changes may invalidate conservatively. Metadata, names, shape groups, onion skin, tags, frame durations and construction review must remain available without fetching the full graph. Animation preview must request missing frames deliberately and avoid rendering an empty cell as real artwork. Use bounded scheduling or worker rendering where observed native render cost would otherwise block interaction.

## Generator lifecycle

Keep the current generator command, args, operation array/object report forms and producer/source verification. Spool stdout into an owned file with backpressure; abort/timeout terminates only that spawned process and closes its streams. Bound stderr retention and disclose truncation. Check byte and operation/work limits separately. Parse the owned output after successful child completion; cleanup occurs on every terminal path. Build cancellation is cooperative at existing synchronous render boundaries; do not claim it preempts arbitrary native work instantly.

## Behavior gates

- A real streamed valid JSON file larger than 64 MiB imports into a new disposable session; progress is observable and no browser JSON envelope contains the file.
- Gzip source and decompressed budgets are independent; truncated/invalid input, exceeded budgets, aborted upload, worker failure and canceled validation leave the original session/drafts unchanged and close owned resources.
- Session changes before activation reject publication; job cancellation still works after that change. Failed prospective metadata persistence rolls back completely.
- A generator emitting more than 8 MiB succeeds through the normal build path; malformed output, timeout, abort and runaway output preserve existing published artifacts and leave no owned spool behind.
- Progressive connection and frame access tests show no complete graph transfer, bounded responses/cache, correct selection/edits/undo and rejection of stale session/revision data. Legacy consumers still pass their existing tests.
- The complete detailed animation opens through this official path in an isolated database. Report source sizes, peak memory, first interactive/frame time and later frame latency, with actual native thumbnail render counts and exact raster parity.

The third milestone replaces the validated snapshot/storage representation with the versioned shared-geometry codec. It must not weaken these job, identity, rollback or compatibility gates.
